# O1.1 Delivery Limitation (launch blocker note)

Status: accepted limitation of this slice. Required provider work is
deferred to P8.1C / O4; this note prevents silent mis-launch.

## What O1.1 does

`POST /api/v1/auth/signup` and `POST /api/v1/auth/verify/resend` create a
`email_verifications` row and enqueue `template=verify_email` on the
existing transactional outbox (`notification.requested`, refs only).
The outbox worker delivers through the configured `NotifyPort` adapter.

## What O1.1 does NOT do

No production email provider exists in this repo. `NOTIFY_PROVIDER` admits
only `dev-console` (development logging, `health() == False`) and `none`
(explicitly unavailable: every send raises, outbox retries 8x with
backoff, then marks `dead`).

## Launch rule

- Do NOT expose `POST /api/v1/auth/signup` on preview/production while
  `NOTIFY_PROVIDER=none`: accounts and challenges would be created but the
  verification link could never be delivered. The endpoint answers `202`
  either way (no account oracle) and logs a server-side warning
  (`signup accepted while NOTIFY_PROVIDER=none`), but nothing tells the
  user delivery is impossible.
- The unblocking work is a real email provider (selection, credentials,
  signature verification if applicable, receipting) plus the P8.1C
  dispatcher (server-side recipient resolution per
  `modules/notifications/eligibility.py`). None of that is in O1.1.
- Dev/test loop: with `ENV=dev|test` and `DEV_NOTIFICATIONS_ALLOW=true`,
  the endpoint logs a single `DEV-ONLY verification link: /verify?token=…`
  line. This branch is unreachable in preview/prod (boot validation
  forbids the flag outside dev/test; the dev adapter refuses to start).
  Raw tokens never enter the outbox payload (`token` is a forbidden port
  key), audit events, or API responses.

## Verification of this limitation

- `tests/api/test_signup_api.py::test_no_raw_token_at_rest` proves the
  outbox payload carries refs (`user_id`, `verification_id`) and no token.
- `test_no_raw_token_in_logs_except_dev_marker` proves the only log line
  containing a raw token is the gated `DEV-ONLY` line.
